Lumera is a Layer 1 blockchain built for permanent data and decentralized intelligent services. Files stored on Lumera are erasure-coded, distributed across a network of independent SuperNodes, and retained indefinitely for a single upfront payment. The network continuously re-verifies that stored data is intact and retrievable, and records those proofs on chain.

Unlike general-purpose chains, Lumera is purpose-built for workloads that need provable data and verifiable execution. Its defining structural choice is the Validator-SuperNode architecture: validators secure consensus, while SuperNodes, dedicated servers bonded to those validators, perform the heavy work of storing data, verifying content, and running compute. Consensus stays light and fast; storage and computation scale independently of it.

Lumera is building infrastructure for AI agents on this foundation: persistent memory, agent-owned identity, verifiable execution, and settlement. The storage layer, Cascade, is live on mainnet and fully documented here. Documentation for each new capability is added as it ships.

## The Action and Agent framework

Lumera's execution model separates atomic work from orchestration. This distinction is fundamental to how the network operates and how it extends.

**Actions** are low-level, stateless operations executed by SuperNodes. Each Action is registered on chain, escrows a fee, moves through a defined lifecycle, and settles when the work is verifiably complete. Actions available today:

| Action | What it does |
| --- | --- |
| **Cascade** | Stores data permanently, erasure-coded across SuperNodes with continuous retention proofs |
| **Sense** | Records verifiable statements about content, starting with near-duplicate and manipulation detection |

**Agents** are higher-level, goal-oriented processes that compose Actions into workflows: retrieving data, verifying it, computing over it, and acting on the result without a human driving each step. Agents are the reason the primitives below them are designed the way they are. An autonomous process needs memory that outlives its session, work it can prove to a counterparty, and settlement that does not depend on a trusted intermediary.

Because Actions are modular and share one lifecycle, registry, and settlement path, new capabilities extend the framework rather than replacing it. Every Action produces the same kind of on-chain evidence, which is what makes composition safe.

## What you can build today

Cascade is live on mainnet. Store any data and it is encoded with RaptorQ erasure coding and spread across economically bonded SuperNodes, so any sufficiently large subset of the pieces can rebuild the original. No single node, and no single company, can lose or delete it. Ongoing retention is funded by Everlight, an endowment mechanism that pays operators for as long as they hold data, which is what makes a one-time payment sustainable.

## How the network runs

Validators secure the chain through delegated proof of stake, proposing and signing blocks and voting on governance. A validator can also run a SuperNode, earning Proof-of-Service rewards from service fees on top of staking rewards. A SuperNode stays active only while its validator meets the self-stake threshold, which keeps service capacity tied to real economic commitment.

The chain is the control plane: it records requests, escrows fees, tracks results, and holds identity and governance state. SuperNodes are the execution and memory planes: data moves directly between clients and SuperNodes and never passes through consensus. LUME is the native asset for staking, transaction fees, and service payments, and all protocol revenue accrues in it.

## Where this is going

Permanent, provable storage is the first of five capabilities Lumera is building for agents:

1. **Memory** - durable, verifiable state that survives sessions, models, and providers. Live today through Cascade.
2. **Identity** - an on-chain identity an agent owns, with delegated authority and explicit spending limits.
3. **Verifiable execution** - work that produces a signed receipt, so a counterparty can confirm what ran and what it cost.
4. **Settlement** - payment that releases only against acknowledged work, with disputes resolved from evidence.
5. **Trust** - a record compiled from what participants actually did rather than what they claim.

Each capability builds on the last, and each is expressed through the same Action and Agent framework. Everything documented here works today.
