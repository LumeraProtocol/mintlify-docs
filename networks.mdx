Lumera Protocol runs two public networks, a production mainnet and a testnet for development and operator onboarding. Both use the same `lumerad` binary. Only the chain ID, genesis file, and seeds differ. Pick your network in the tabs below.

<Tabs>
  <Tab title="Mainnet">
    Mainnet is the production network. Real LUME is staked and Cascade files are stored for good. Protect mainnet keys with production-grade security practices.

    ### Network parameters

    | Parameter | Value |
    |---|---|
    | **Chain ID** | `lumera-mainnet-1` |
    | **Native denom** | `ulume` |
    | **Minimum gas price** | `0.025ulume` |
    | **Explorer** | [Lumera Portal](https://portal.lumera.io/lumera-mainnet-1) |

    ### Genesis file

    Download the mainnet genesis file from the lumera-networks repository.

    ```bash
    curl -o genesis.json https://raw.githubusercontent.com/LumeraProtocol/lumera-networks/master/mainnet/genesis.json
    ```

    Place it in your node's config directory.

    ```bash
    cp genesis.json ~/.lumera/config/genesis.json
    ```

    ### Seed nodes

    Add the seed to `~/.lumera/config/config.toml` under `[p2p]`.

    ```toml
    seeds = "f64b9efc5747cc3556bdc281dab930a716dd63af@seeds.lumera.io:26656"
    ```

    ### Minimum gas price

    Set the minimum gas price in `~/.lumera/config/app.toml`.

    ```toml
    minimum-gas-prices = "0.025ulume"
    ```

    ### Quick config summary

    ```bash
    # Initialize node (replace <moniker> with your node name)
    lumerad init <moniker> --chain-id lumera-mainnet-1

    # Download genesis
    curl -o ~/.lumera/config/genesis.json \
      https://raw.githubusercontent.com/LumeraProtocol/lumera-networks/master/mainnet/genesis.json

    # Set seeds in config.toml
    sed -i 's/seeds = ""/seeds = "f64b9efc5747cc3556bdc281dab930a716dd63af@seeds.lumera.io:26656"/' \
      ~/.lumera/config/config.toml

    # Set gas price in app.toml
    sed -i 's/minimum-gas-prices = ""/minimum-gas-prices = "0.025ulume"/' \
      ~/.lumera/config/app.toml

    # Start the node
    lumerad start
    ```

    <Warning>
      Never share your validator key at `~/.lumera/config/priv_validator_key.json` or your operator key mnemonic. Back both up securely before starting the node.
    </Warning>
  </Tab>

## Hardware requirements

The table shows the minimum recommended hardware for a production validator. SuperNode operators should provision the same or better to handle Cascade and Sense workloads.

| Component | Minimum |
|---|---|
| **CPU** | 8+ cores |
| **Memory** | 64 GB RAM |
| **Storage** | 2 TB+ SSD |
| **Network** | High bandwidth with low latency |

<Warning>
  Underpowered validators miss blocks, get jailed, and lose staked LUME to slashing. Underpowered SuperNodes fall out of the active top list and miss rewards.
</Warning>

Chain state and the Cascade store grow over time. Plan capacity headroom and monitor disk usage.

## Public endpoints

Public endpoints let you query chain state without running a node. They are rate limited, so run your own node for production workloads.

| Service | Mainnet | Testnet |
|---|---|---|
| **gRPC** | `grpc.lumera.io:443` | `grpc.testnet.lumera.io:443` |
| **RPC** | `https://rpc.lumera.io` | `https://lumera-testnet-rpc.polkachu.com` |
| **LCD (REST)** | `https://lcd.lumera.io` | `https://lumera-testnet-api.polkachu.com` |
| **SN-API** | `https://snapi.lumera.io` | `https://snapi.testnet.lumera.io` |

The official mainnet RPC and LCD hosts can be intermittent. Community providers such as [Polkachu](https://www.polkachu.com/networks/lumera) also serve public Lumera endpoints, and validator snapshots are linked from the [validator setup guides](/validators-mainnet/node-setup).

## EVM access

From `v1.20.0`, nodes enable the EVM JSON-RPC server and OpenRPC discovery by default, so a node you run also serves Ethereum tooling such as Hardhat and Foundry. Testnet runs the v1.20 line today. Mainnet is still on `v1.12.0` and gains EVM support with its upgrade. See [Smart contracts](/smart-contracts/overview) for details.
