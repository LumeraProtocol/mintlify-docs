A SuperNode is a companion application that runs alongside your Lumera Protocol validator. It extends your role beyond block production. Your SuperNode stores files for Cascade, evaluates content for Sense, and earns LUME rewards for the work. Every SuperNode is tied to a registered validator identity, so you need an active validator first.

<Note>
Existing operators. The `v1.20.0` EVM upgrade changes account key derivation. On networks that have upgraded (testnet today), the daemon can migrate your account once `evm_key_name` is set in `config.yml`, or you can migrate first yourself. See the [EVM upgrade page](/upgrades/evm-upgrade).
</Note>

## Services you provide

SuperNodes run two complementary services.

**Cascade** is permanent, redundant file storage. When a user submits a Cascade action, your SuperNode encodes the file with RaptorQ erasure coding, splits it into redundant symbols, and distributes them across the P2P network. The original file can be rebuilt even when a subset of symbols is lost. No node needs to hold a full copy.

**Sense** protects content integrity. Participating SuperNodes independently evaluate submitted media for near duplicates and reach a consensus backed verdict. This stops the same content from being registered repeatedly under different identities.

## How rewards work

The protocol selects a set of top ranked SuperNodes for each action, based on stake and performance. If your SuperNode is selected and fulfills the action correctly, you receive a share of the action fee. This is proof of service income, separate from validator staking rewards. Higher stake and reliable uptime improve your rank and your earning opportunities.

## Roles

| Role | Description |
|------|-------------|
| SuperNode operator | A registered validator who runs the `supernode` binary, serves Cascade and Sense actions, and earns rewards |
| User | Any account that submits a Cascade or Sense action and pays the action fee |

## Requirements

- An active Lumera validator in the bonded set. The SuperNode signs with an account tied to your validator identity.
- Combined stake that meets the on-chain minimum. Registration uses a dual source model that adds your validator self delegation and the SuperNode account delegation. Check the current minimum with `lumerad query supernode params`.
- Recommended hardware of 8 or more CPU cores, 64 GB RAM, 2 TB or more SSD storage, and a high bandwidth connection.
- Open ports `4444` (gRPC service) and `4445` (P2P).
- A reachable Lumera gRPC endpoint, `localhost:9090` when the validator runs on the same machine.

## Architecture

The SuperNode reads action requests and submits transactions through your node's gRPC endpoint. It exchanges RaptorQ symbols with other SuperNodes over a distributed hash table on port `4445`. Clients reach its own gRPC API on port `4444`.

```
 Client application
        │
        │ gRPC (port 4444)
        ▼
 ┌─────────────┐        gRPC (port 9090)      ┌──────────────────┐
 │  SuperNode  │ ◄──────────────────────────► │ Lumera full node │
 │             │                              │ (your validator) │
 └──────┬──────┘                              └──────────────────┘
        │
        │ P2P DHT (port 4445)
        ▼
 Other SuperNodes
```
