title: "Set up a Lumera validator node"
sidebarTitle: "Node setup"

This guide takes you from a fresh server to a fully synced Lumera Protocol node. Follow the steps in order. Each step assumes the previous one completed successfully. Once your node is synced, continue to [create your validator](/validators/create-validator).

<Steps>

### Install prerequisites

Before building `lumerad`, your server needs Go 1.26 or later, `make`, `git`, and the C toolchain that CGO uses to compile `libwasmvm`.

```shell
# Ubuntu / Debian
sudo apt-get update
sudo apt-get install -y build-essential git curl jq

# Install Go (match the version in go.mod)
GO_VERSION=1.26.0
curl -OL https://go.dev/dl/go${GO_VERSION}.linux-amd64.tar.gz
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf go${GO_VERSION}.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin:$HOME/go/bin' >> ~/.profile
source ~/.profile
go version
```

Confirm Go reports the version you installed before continuing.

<Note>
`libwasmvm` is compiled automatically as part of `make build`. If the build fails with a missing shared library at runtime, download the correct `.so` from the [CosmWasm/wasmvm releases](https://github.com/CosmWasm/wasmvm/releases) page and place it in `/usr/lib/`.
</Note>

### Build lumerad

Clone the Lumera repository, compile the binary with `make build`, and move it onto your `$PATH`.

```shell
git clone https://github.com/LumeraProtocol/lumera
cd lumera
make build
# Binary is written to build/lumerad
sudo mv build/lumerad /usr/local/bin/
lumerad version
```

Verify the output shows the version you just built. If you see `command not found`, confirm `/usr/local/bin` is in your `$PATH`.

<Tip>
To build with debug symbols for profiling or crash analysis, run `make build-debug` instead. Do not use the debug binary in production. It is larger and slower.
</Tip>

### Initialize your node

`lumerad init` creates the home directory at `~/.lumera`, generates your node key and private validator key, and writes default `config.toml` and `app.toml` files.

<Tabs>
  <Tab title="Mainnet">
    ```shell
    lumerad init <moniker> --chain-id lumera-mainnet-1
    ```
  </Tab>
  <Tab title="Testnet">
    ```shell
    lumerad init <moniker> --chain-id lumera-testnet-2
    ```
  </Tab>
</Tabs>

Replace `<moniker>` with a readable name for your node, for example `my-validator`. This name appears in explorers and peer lists.

<Warning>
`lumerad init` generates `~/.lumera/config/priv_validator_key.json` and `~/.lumera/config/node_key.json`. Back up both files securely before you go any further. Losing `priv_validator_key.json` means you can no longer sign blocks and your validator gets slashed for downtime.
</Warning>

### Download the genesis file

Replace the default `genesis.json` scaffold with the official network genesis.

<Tabs>
  <Tab title="Mainnet">
    ```shell
    curl -o ~/.lumera/config/genesis.json \
      https://raw.githubusercontent.com/LumeraProtocol/lumera-networks/refs/heads/master/mainnet/genesis.json
    ```
  </Tab>
  <Tab title="Testnet">
    ```shell
    curl -o ~/.lumera/config/genesis.json \
      https://raw.githubusercontent.com/LumeraProtocol/lumera-networks/refs/heads/master/testnet-2/genesis.json
    ```
  </Tab>
</Tabs>

Verify the hash of the downloaded file.

```shell
sha256sum ~/.lumera/config/genesis.json
```

Compare the output against the hash published in the [lumera-networks repository](https://github.com/LumeraProtocol/lumera-networks) to confirm you have the right file.

### Configure seeds

Open `~/.lumera/config/config.toml` and set the `seeds` field so your node can discover peers on startup.

<Tabs>
  <Tab title="Mainnet">
    ```toml
    seeds = "f64b9efc5747cc3556bdc281dab930a716dd63af@seeds.lumera.io:26656"
    ```
  </Tab>
  <Tab title="Testnet">
    ```toml
    seeds = "faff7c1350468c53121a669ac40e317a4a70c425@seeds.testnet.lumera.io:26656"
    ```
  </Tab>
</Tabs>

If you use a sentry architecture, leave `seeds` empty on the validator and put your sentry addresses in `persistent_peers` instead. The [operations page](/validators/operations) covers peer settings in detail.

### Set the minimum gas price

Open `~/.lumera/config/app.toml` and set the minimum gas price your node accepts. Transactions offering less are rejected at the mempool level.

```toml
minimum-gas-prices = "0.025ulume"
```

The value is the same on mainnet and testnet. Setting it lower invites mempool spam. Setting it higher can reject legitimate transactions.

### Start the node and sync

Start `lumerad` and let it sync blocks. A fresh node can take hours to days depending on chain height and hardware.

```shell
lumerad start
```

Check progress from a second terminal.

```shell
lumerad status 2>&1 | jq .SyncInfo
```

Wait until `"catching_up": false` before you register a validator. The chain rejects a create-validator transaction from a node that is still behind.

<Tip>
Run `lumerad` as a `systemd` service so it restarts after reboots and crashes. The [operations page](/validators/operations) has a sample unit file.
</Tip>

</Steps>
