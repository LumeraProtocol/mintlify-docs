Your node is built and fully synced. This page registers it as a validator. You create an operator key, fund it, submit the create-validator transaction, and verify you entered the active set. If your node is not synced yet, start with [node setup](/validators/setup).

<Steps>

### Create a validator key

Generate the operator key that signs your create-validator transaction and holds your self-delegation.

```shell
lumerad keys add <key-name>
```

The command prints your address and a mnemonic. Write down the mnemonic and store it offline. It is the only way to recover the key if your server is lost.

```shell
# Confirm the key was created
lumerad keys list
```

<Note>
Since the `v1.20.0` EVM upgrade, new keys derive with `eth_secp256k1` on coin type 60. The same account has a `lumera1...` form and a `0x...` form. See the [EVM upgrade page](/upgrades/evm-upgrade) if you are migrating a validator that existed before the upgrade.
</Note>

### Fund the address

The key needs enough LUME for the self-delegation plus transaction fees.

<Tabs>
  <Tab title="Mainnet">
    Transfer LUME to the address shown by `lumerad keys list`. You need at least 1 LUME (1,000,000 ulume) for the minimum self-delegation plus a small amount for fees.
  </Tab>
  <Tab title="Testnet">
    Request testnet LUME from the [faucet](/faucet) or ask in the [Lumera Discord](https://discord.com/invite/lumeraprotocol).
  </Tab>
</Tabs>

Confirm the balance arrived before continuing.

```shell
lumerad query bank balances <your-address>
```

### Submit the create-validator transaction

This transaction registers your consensus public key and your commission terms on chain.

<Tabs>
  <Tab title="Mainnet">
    ```shell
    lumerad tx staking create-validator \
      --amount=1000000ulume \
      --pubkey=$(lumerad tendermint show-validator) \
      --moniker="<your-moniker>" \
      --chain-id=lumera-mainnet-1 \
      --commission-rate="0.10" \
      --commission-max-rate="0.20" \
      --commission-max-change-rate="0.01" \
      --min-self-delegation="1" \
      --from=<key-name> \
      --gas=auto \
      --fees=5000ulume
    ```
  </Tab>
  <Tab title="Testnet">
    ```shell
    lumerad tx staking create-validator \
      --amount=1000000ulume \
      --pubkey=$(lumerad tendermint show-validator) \
      --moniker="<your-moniker>" \
      --chain-id=lumera-testnet-2 \
      --commission-rate="0.10" \
      --commission-max-rate="0.20" \
      --commission-max-change-rate="0.01" \
      --min-self-delegation="1" \
      --from=<key-name> \
      --gas=auto \
      --fees=5000ulume
    ```
  </Tab>
</Tabs>

The flags control your economics and identity.

| Flag | Description |
|------|-------------|
| `--amount` | Initial self-delegation in `ulume`. 1,000,000 ulume equals 1 LUME. |
| `--pubkey` | Your consensus public key. The `show-validator` subcommand reads it from disk. |
| `--commission-rate` | The share of delegator rewards you keep. 0.10 means 10 percent. |
| `--commission-max-rate` | A hard ceiling you can never raise your commission above. |
| `--commission-max-change-rate` | The most you can change commission within 24 hours. |
| `--min-self-delegation` | The `ulume` you must keep self-delegated. Dropping below unbonds you. |

Commission terms are public and delegators compare them. The maximum rate and maximum change rate are permanent, so choose them carefully.

### Verify you are in the active set

Query your validator record.

```shell
lumerad query staking validator $(lumerad keys show <key-name> --bech val -a)
```

A `status: BOND_STATUS_BONDED` response confirms you are active and signing. You can also find your validator on the [Lumera Portal](https://portal.lumera.io/lumera-mainnet-1) by its moniker.

### Back up everything

Two things are irreplaceable. Copy both off the server now.

- `~/.lumera/config/priv_validator_key.json` is your consensus identity. Anyone holding it can sign blocks as you, and losing it ends your validator.
- The mnemonic of your operator key controls your self-delegation and rewards.

<Warning>
Never run two nodes with the same `priv_validator_key.json`. Signing two blocks at the same height is equivocation and leads to permanent tombstoning with slashed stake.
</Warning>

</Steps>
